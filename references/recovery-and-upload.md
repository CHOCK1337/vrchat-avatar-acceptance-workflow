# 失败、恢复与上传

## 最小失败处理
沿源素材 → Provider 源配置 → 处理产物 → 最终显示/控制找第一处分歧。只修最优先的一个具体原因。
预算是**一个资源同一失败**的一次定向纠正与一次复查；不是一个方法两次、换方法再两次、换子 Agent 再两次。转换/外扩/遮罩不能各自重置预算。
已知仍失败且可完整撤销：移除该资源新增引用，隔离它，继续其他资源；不把失败候选当下一轮源。无法知道如何恢复或需用户选择：暂停整个任务。错误未知但相关资料还未读完：先做一次范围有限的诊断，不立刻问一堆技术问题。

失败缓存只在同源/目标/相关状态/资源版本/Provider/工具版本/设置未变时复用。仅 Skill 标点变动不能使所有失败失效。新相关能力或新 Profile 才可重新尝试一次。
不要求用户制作 FailureCard；从现有任务记录中自动保留：期望、实际、首处分歧、修改与证据，结束写进短报告即可。普通任务不现场开发回归测试。

## 发布是独立动作，但可以预先授权整个任务
- 用户明确“装配并上传”或点击包含上传的入口：记录本任务范围内自动 Private 发布授权。不要每步再问。
- 本次“连接/工作流试跑”：默认 `workflow_test`，没有真实上传。不能因为过去聊天授权过其他任务而自动发布新任务。
- 不强制 Build & Test；SDK 为上传生成 AssetBundle 是必需的 build，不是 Build & Test。
- 用户取消、改变目标/Blueprint、暂停或要求手动上传时，立即停止后续发布调度。已经发往远端的请求无法保证撤销，需要确认实际结果。

## 上传前只做这些必要检查
精确候选、当前场景/Prefab Stage、已保存内容以及所用版本一致；五问开工卡已确认；全部合格衣服/插件已完成统一本地观察；失败资源安全隔离；所有待选择问题已解决；若开工卡将体积设为上传门，则对应指标已有本次实测且未超限；SDK 能校验/构建；账号拥有目标 Blueprint。
源有已有故障且用户选择接受时，只接受该显式已知问题，不能因此忽略新故障。SDK 硬错误/无权限/编译失败不能由“仍然上传”绕过。
性能 Very Poor 按用户规则提示，不额外启动激进优化或阻止 SDK 允许的发布。

用户指出可视化缺陷后，相关本地通过与上传就绪立即作废；先恢复最近可信候选并完成受影响统一检查。已知穿模、毛刺、缺块或体积硬上限超标不能由“仍然上传”绕过。

## 发布执行
使用已安装 SDK 的受支持接口和现成上传动作。类型、方法及完成回调必须在当前版本确认，不把本 Skill 文本当成可调用 API。
已有本人 Blueprint → 更新；无 ID → 新建；404/归属不明 → 先核验账号/ID与远端状态，不自行清空 ID 新建重复模型。
更新或新建都设 Private，保留用户其余元数据，不未经授权公开。不得截取账号密码/导出 token，登录/2FA 由用户在 SDK 正常完成。
不得向用户索取、复述或把登录凭据写进聊天、AssemblyTask、截图、报告或学习记录；用户误发时后续交接自动脱敏。
一次明确发布提交，等待完成事件或有上限的低频状态检查。输出不明/pending 时只查询现状，不再发第二次 BuildAndUpload。不要在发布阶段临时写持久 C# 造成 Domain Reload。
最少核对返回 Avatar ID、Private、版本/更新信息和终态；不常规重新下载整个远端 AssetBundle 做哈希回读。仅有明确“上传错版本”证据才升级调查。

## 结果语言
`上传成功` = 本次已授权的远端提交确认，流程结束；`客户端动态未运行`可同时存在，二者不矛盾。
`LOCAL_OK` = 指定本地检查完成；`本地待处理` = 必要项缺失/失败；`暂不支持` = 当前路由没有能力。
不再用“687/687”、“组件存在”或“包自测通过”证明整个模型正常。
公开平台内容与素材许可必须遵守；Private 或默认关闭不豁免平台规则，也不豁免模型服务限制。

## 复发与经验（RC2）
一次明确用户纠正即记录，不必等连续三次。相同输入和相同 requirement 下的复发会暂停相关已生效修法；在新的有效证据出现前不要原样重用。经验只能帮助选择当前允许的动作，不能重置“同问题一次纠正”的预算，也不能为了寻找新经验多试一种方法。
用户未继续投诉不等于旧问题已修好，上传成功不等于可把某个局部修法学为成功。上传授权、取消、中断远端核对均沿用本文件已有规则；学习记录没有覆盖它们的权限。
