# 附件与插件：不要求错误的身体 Profile

## 附件路由
作者预设优先。软性/贴身穿戴物需要骨架跟随且已匹配目标时采用作者或 MA 衣服安装路线；硬质头饰、武器、手持物、包和悬挂物采用作者挂载、Bone Proxy 或合适约束。
`SkinnedMeshRenderer` 可能只用于一条挂件骨骼；不能据此强制走服装变形。作者规定带骨架的硬物同样保留其 rig。
结构不明先看组件和说明。只有确实支持且可回滚的 MA 操作才试一次；不是“任何附件先调用一个不存在的 MA AutoFit API”。异常回退锚点路线消耗同一件的纠正预算。

## 防止小芽悬空的具体执行链
1. 找到真实挂载意图、目标 Head/Hand/Chest 等，以及道具自身接触点。Head 骨位置不是头皮表面；Bounds 最低点也不是所有道具的接触点。
2. 读作者 Root 与可见 Mesh 子节点的相对 Transform、世界尺度和 Pivot；保留有效预置，不无脑把 localPosition 设为 0。
3. MA Bone Proxy 的 attachment mode（归零/保持世界位姿）和 Match Parent Scale 会改变最终位置/尺度。核对本机版本字段，不凭旧截图猜选项。
4. 只允许一条实际驱动链；合法的层级父子关系与 Proxy 共存不自动算双重驱动。拒绝的是同一对象同时被不相容约束重复驱动。
5. 生成/预览后核对最终目标和可见几何位置；拍目标部位正面与侧面/斜侧近景，实际打开查看。饰品悬空、穿入、比例错误不能用“已挂到 Head”通过。
6. 摆动目标骨骼的一个典型方向，确认相对位置跟随。缺此能力只能说明位置检查完成，不能宣称动态完全正确。
7. 已知位置误差允许局部修正一次；无可靠接触意图则暂停问用户，而不是批量猜位置。

官方 Bone Proxy 文档：https://modular-avatar.nadena.dev/docs/reference/bone-proxy

## 功能插件
GoGoLoco 等名称是接入线索，不是白名单自动通过凭证。ABT/UruBlink/Stardust 等若存在多个同名版本，先查当前作者说明；不要用名称猜组件。菜单、动画、Contact、PhysBone 或道具不是体型转换。
用一次小型责任记录关联：作者源配置 → 实际 Provider → 参数/控制器 → 最终对象或效果。已有同类正常功能优先保留；可分离的新能力单独接入。确实二选一时暂停整个任务问一次。
已验证版本走专用路径；标准 Provider 陌生插件走通用接入。自带 Editor 脚本可触及整个项目，不因运行在生成副本就自动可信。未知全局修改入口先读影响范围，不自动执行脚本安装器。

插件准入还要声明菜单类别和安装目标：动作类进入 `动作`，功能类进入 `功能与插件`，全局用户设置才进入 `设置`。不得让每个 Menu Installer 默认追加到根菜单。按 [menu-planning-and-localization.md](menu-planning-and-localization.md) 使用任务生成 wrapper 或 provider 支持的 `Install To` 接入；保留品牌名和作者控制语义，只汉化用户可见用途，不翻译内部参数/Animator/Provider 标识，也不原改 vendor 菜单。

在批量写入前一次性完成全部插件的只读准入：版本/作者说明、依赖、已有同类功能、参数/菜单/FX/Descriptor 写入面、全局 Editor 安装器影响、预计构建/交付体积以及可回滚边界。与衣服一起进入统一批次；不能装一个插件就跑一轮完整功能验收。

每个插件安装后只做灾难性烟雾检查：Provider 正常结束、无新增编译/缺引用、精确 Avatar 仍存在、没有整体覆盖 Descriptor/FX/menu、没有意外根层平铺，或造成不可恢复的重复 Writer。通过记 `INSTALLED_UNVERIFIED`。所有合格衣服与插件装完后，才在唯一最终候选上统一遍历菜单图并驱动入口→参数→最终效果的 Happy Path；影响共享菜单/参数的插件同时复测相关衣服开关及 `A → B → A → 默认恢复`。

## 可选功能与核心功能
衣服必要骨架、形变、高跟鞋、物理、独立部件、遮罩恢复、基本开关属于核心。可分离的装饰音效/粒子冲突可降级并告知；不是把用户明确要的功能统统标可选。
原有 FX/Descriptor/全部菜单不得整体覆盖；未知 Camera/Contact/PhysBone 不得全部禁用。安装失败需要移除本件新增引用，不删除其他 provider 的正常内容。
成人标签、Private 状态或改名不提供绕过服务安全限制的许可；普通非露骨技术装配按同一流程处理。不要通过隐藏资产用途、屏蔽内容或更换模型来逃避限制；不包含自动构建露骨性互动能力的承诺。
