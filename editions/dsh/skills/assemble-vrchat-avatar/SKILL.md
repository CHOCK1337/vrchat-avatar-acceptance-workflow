# VRChat 改模 — 0.3.2-local5-dsh · DSH 任务与结果对齐

**Goal:** complete the requested edit with a correct visible result and minimal interruption. Use the existing Unity tools; this Skill does not implement a fitter or certify images. Respect host/project safety rules.

## Start with the task, not a questionnaire
Read the user's target, assets, appearance, requested method, preserved features, budget and delivery. Reuse explicit current-task choices. Briefly state the interpreted edit and start read-only discovery; do not demand confirmation of five technical contracts when the request is already clear. Ask one consolidated question only for a real missing choice, a method conflict, an ambiguous target, or an unsupported necessary operation. Do not ask whether ordinary checking or reversible generated-asset changes are allowed.

Verify the exact open Unity project/target, unsaved work and relevant compile state once. Reuse the current working MCP and author dependencies; never guess an instance or switch body/Avatar to make a package fit. Local work is the default when this task has not authorized upload. Ordinary tasks inherit the current model. Collaboration and HTML require the user's choice; an already explicit choice is not asked twice. No new GUI in this release.

## DSH host integration
When running in DSH, read the core page [DeepSeek execution rules](../../DEEPSEEK_RULES.md) at task start/resume; its table names the one playbook to open for each symptom. Open [dsh-execution.md](references/dsh-execution.md) only for routing problems or MA exclusive-group probes. The rules cover actual garment geometry, source/processed/preview identity, body-hide restoration, real menu input and correctly framed visual evidence. Establish one visible working increment on a new preview/control path before expanding a batch; reuse already valid evidence. Select the exact session project/binding, preserve the latest effective requirements, and use original image pixels. For changed MA exclusive wardrobe/hair groups, use the bounded read-only probe once at the batch boundary, then validate actual controls and the normal default view. Source checks, provider output, operated controls, visual checks and SDK results are separate records; a tool receipt or addressed feedback is not acceptance.

## Routine route
For DSH workbench preview/menu validation, use [the verified preview entry](references/dsh-preview-api.md). Keep your consumer lease active but **idle** throughout temporary preview, settling and image capture; **busy** is for persistent Avatar edits and blocks preview controls/animation. Check both nested executionSuccess and the entry's ok/error; use exact candidate identity and inspect the returned original PNG. Do not probe private APIs or clear logs repeatedly.

1. Identify selected resources and their actual dependencies, not the whole project. For batches, preflight all selected resources, then install serially into one candidate. Keep the author's usable control source/menu. Read [routes.md](references/routes.md) only for the relevant operation.
2. Preserve the source and shared assets. Modify the task copy; clone only the asset actually being changed. Keep enough old values/references to undo this edit. Do not copy the project, Library/Temp, or export unitypackages for each change. See [execution.md](references/execution.md).
3. **Do the edit.** Reuse installed actions and verified APIs. Existing bounded Editor operations are allowed, but do not invent a generic fitter, giant Builder, custom screenshot framework or test suite during assembly. A missing capability is a concrete limit, not a reason to keep auditing.
4. After each installation, look for immediate destructive faults: new compile/reference errors, wrong target, detached geometry, accidental body hiding or global controller replacement. Stop at an observed fault. Otherwise continue; no full per-item build/pose review. A single edit is simply a one-item batch.
5. After a full Avatar assembly, or an explicit optimization request, run one conservative final optimization using [optimization.md](references/optimization.md): reuse installed AAO on the private authoring candidate, preserve source/feature/parameter semantics, choose texture copies by actual material use and quality, and generate the processed candidate. Ordinary individual edits stay scoped unless optimization is requested. Explicit no-optimization/no-build constraints take precedence. Reuse completed work on the same candidate; do not optimize every view or asset selection. Then freeze the current candidate and check only the requested and genuinely affected results using [review.md](references/review.md). See the normal-material image yourself and exercise real relevant controls. Numerical or structural success is not visual success.
6. Locate one first divergence, correct it once, recheck affected results once. A changed model/agent/method does not reset that budget. Isolate a failed optional resource only when authorized and fully reversible; required missing content or unresolved shared damage remains unfinished. Do not publish an incomplete promised result as complete.
7. For full-model delivery or an explicit optimization request, obtain one final local SDK Build measurement unless the task excludes builds; reuse an identical successful build or the necessary upload build. Other tasks measure only where the task/SDK delivery requires it. Reuse an existing real baseline when comparing; without one report final measurements without inventing reductions. If a build callback omits statistics, read the actual built bundle with the installed SDK rather than rebuild. Record optimization, actual controls/closeup checks, candidate identity, metrics and limits in the current QuickTask. See [optimization.md](references/optimization.md) and [delivery.md](references/delivery.md). No new 300 MB/rank target, pre-install baseline, Build & Test, upload permission, or full attribution audit.
8. Report the edited result, what was actually seen/operated, remaining defects, exact candidate and delivery result in a short note. Upload success and local quality are separate facts. No claims of unobserved client/network effects.

## Less work, not less truth
Same relevant inputs/state/view/pipeline and an already inspected result: reuse it. A first observation, changed pose, corrected preview, user defect or changed dependency is a valid reason to inspect. Never rename old pictures as new evidence. A quick final default view catches shared-state regressions. Do not treat every visible body-colored pixel as clipping.

A user's explicit requested method is not overridden by a default route. Explain the specific conflicting evidence once and ask before substituting methods. Never fake a MochiFitter run, change the body identity, or clear all body shapes to make a route look successful.

## Optional helpers, not new gates
Use a small `QuickTask.json` outside Assets for continuation; notes must retain the user's explicit requirements. [helper-usage.md](references/helper-usage.md) describes `quickflow.py` for scoped check suggestions, evidence-record reuse and nested execution receipts. Use it when it saves work, not on every tool call. It cannot see Unity or authenticate observations. Its failure must not start a helper-debugging loop.

Do not call the old `workflow.py`/`task_store.py` in ordinary tasks: their strict release contracts are archived outside the installed Skill. Existing legacy task requirements remain binding; read them without converting or erasing them. See package `MIGRATION.md` once on upgrade.

[collaboration-lite.md](references/collaboration-lite.md) is optional: main alone operates live Unity; selected assistants read bounded snapshots or review the same evidence. Do not switch models, edit global permissions, run role probes, or add reviewers without agreement. A missing agreed independent review is disclosed, not silently self-approved. A skill/model update cannot change the task's quality or retry requirements.

Existing [feedback-memory.md](references/feedback-memory.md) remains available when there is a relevant correction. No new learning agent, screenshots or regression run. Do not preload all references, recursively start another avatar audit Skill, or run this package's developer tests as part of editing an avatar.
