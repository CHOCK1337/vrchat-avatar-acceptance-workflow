## 8. 真正看图，构图覆盖要验收的部位
打开真实原图后再写观察结论。腿部问题需要完整小腿、脚踝和脚的正常材质画面，必要时增加局部/斜侧图；不能用裁到裙摆的图验收腿。
图片文件存在、像素比例、衣片数量、组件数量、NDMF 成功和 SDK 构建都不能证明外观正常。默认图出现明显断腿、缺衣或叠衣时，先定位，停止批量生成无意义截图。

几何测量必须来自能正确求值的实际临时实例，并记录非零有限的网格范围。持久 Prefab 资产上 BakeMesh 得到零点或仅根平移的结果不能作为拟合依据。源/候选对照要使用相同姿态和坐标空间；仅最高点接近不能证明头围或发根贴合。自己搭建的参考组合中某个对象默认 active，也不能直接推断作者要求它必须保留；仍须结合作者配置及实际图像验证。

宽袖、裙摆、发梢等依赖 PhysBone 的部位，要区分物理关闭的绑定静止态与真实动态结果。通过工作台现有“动态预览”控件开启物理，确认 physics_simulated、physics_running 和实际物理链，再等正常 Editor 更新后看图。接口不兼容时记录具体版本与错误，不把静止态直接归咎于模型，也不删物理或骨骼来掩盖预览问题。
物理链注册可能滞后一帧；控件刚提交时读到的链数可能仍属于上一状态。稳定后同时读取选择值、活动组件/链数和图像，再给该状态记结果。
姿势参数改变而画面不动时，先检查真实 Action 状态、输出权重、SDK 行为回调和预览时钟。空白图不等于骨骼跑到画外；用实际骨骼/网格范围确认。不得为尚未定位的预览错误制作 RootT、RootQ 或全肌肉归零片段。Workbench 0.2.12 已修复本地 GM 3.9.8 / SDK 3.10.1 的编辑态回调初始化与混合计时问题，仍须真实动作进入、退出看图。
若当前 DSH 模型/图像通路确实不能读取像素，visual_checked=NOT_RUN，写明已经做到哪层与剩余问题；不能凭路径猜图，也不能未经用户选择自动换模型。
