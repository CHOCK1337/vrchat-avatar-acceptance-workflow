> 本页是 DEEPSEEK_RULES.md 的按需细则，原文自 0.3.2-local4-dsh 规则逐字移入，规则内容未改。

## 10. 完成必须与证据一致
完整成品在最终 SDK Build 前，先用当前安装 SDK 的规则检查处理后候选的硬性限制与贴图导入要求。2026-10-18 的 SDK 3.10.1 实测会拒绝超过256个PhysBone组件（即使服装互斥）及未启用 Streaming Mip Maps 的 mipmapped 贴图；这个版本事实不能无条件套到未来版本。NDMF 的相关警告、可切换预览和较低的活动链数都不能替代 SDK 总量校验。修复贴图导入要求使用候选私有副本并完整重映射，保留源贴图及其导入设置。
AAO 合并可能改变控制层名称和 renderer 数量；在优化后新的依赖hash上复测实际菜单、动态和像素。手工 MergePhysBone 会让每个合并组同时只能抓取一个位置，须明确记录具体组与行为变化，不能宣称与多组件抓取完全等价。不得通过关掉所有抓取、删除必选素材或绕过 SDK 校验掩盖总量超限。
合并 PhysBone 时，比较完整设置和实际对象引用，包括曲线切线、权重、wrap 与链深；只比较曲线的 time/value 或对象名称会漏掉差异。启用条件来自组件所属节点及其祖先，不能用受影响骨骼的父节点代替。收集全部 controller.animationClips，涵盖子状态机和 BlendTree，并检查组件 m_Enabled 动画。主机必须保留原启用条件；不等链深只有在明确证明相关曲线恒定且其余设置一致时才可作为有记录的例外。总量、组数或身份守卫失败必须在保存前停止，不能保存失败候选后再靠文字解释为成功。
遇到动态脚本连续出错，回到已核验的 API 和完整可复用脚本。Unity Behaviour.enabled 是属性，不能用 GetField 读取；EditorJsonUtility 的序列化结构须先实际检查，不能假定所有类型都用相同包裹层。已有完整校验脚本时原样调用，不为了缩短输入重写或移除守卫。
SDK 的 error、finish 事件不一定代表异步 Build Task 已退出。失败时保留回执，等真实Task终态和清理完成后再改候选；新的修复候选才可进行有理由的下一次构建。中间bundle或单个finish回调不能记 sdk_build=PASS。
