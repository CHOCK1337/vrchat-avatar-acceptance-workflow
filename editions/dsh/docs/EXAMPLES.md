# 操作案例：从一个可见增量到完整装配

所有示例均要求使用自己合法取得的素材。产品名是历史案例说明，不是随包资产；不同体型、版本和作者配置要重新核对。以下“真实案例”与“练习步骤”分别标明，不把练习写成已运行。

## 案例一：先装一件同体型衣服（练习）

**用户提示词**

> 在当前工程的指定 Avatar 副本上安装我选中的这件同体型衣服，保留原装。做原装和新衣互斥，并保留衣服作者的部件开关。先完成工作台可见换装，不上传。

**Agent 操作**：核对工程/候选 → 查真实衣片及作者适配体型 → 在私有源副本安装 → 生成处理后候选 → 将工作台绑定到该候选 → 真实菜单 原装→新衣→原装 → 稳定后查看完整身体与腿脚。

**用户应看到**：两个状态的衣片明显不同，回原装恢复身体和原有外观。菜单数量增加但画面没变时，任务未完成。记录源、处理后、预览三者身份。模板：[single-outfit.QuickTask.json](../examples/single-outfit.QuickTask.json)。

## 案例二：反馈腿异常（练习）

**用户提示词**

> 在这张工作台冻结图中，切到这套衣服后小腿变细/缺失。请先确认你看的候选和这张图一致，检查原装遮挡与换装恢复，只修复这一问题，保留鞋袜和作者功能。

**Agent 操作**：读取反馈再取原图 → 查看正常材质完整腿脚 → 比较源和处理输出的实际网格/遮挡消费者 → 找首个差异 → 修正当前候选相关状态 → 真实穿上/脱下/再穿，并查看同一部位。

**不成立的证据**：“清零了所有形态键”“有 0 个报错”“骨骼数组有空槽”“截到了裙摆”均不能证明腿修好。检查非零权重实际是否引用缺失骨骼；未使用的空槽不应触发重建骨架。

## 案例三：拼头＋两发型＋三套衣服＋两道具＋两插件（2026-10-18 真实运行）

本案例由真实 DSH 会话实施装配；父执行器负责独立原图、控件和构建复核。后期复杂修复由父提供校验脚本、DSH 执行。因此它说明工具链能够支持有监督的完整改模，不证明 DeepSeek 对任意 Avatar 全程无人监督都能成功。

| 项目 | 当时使用的素材 |
|---|---|
| 头身拼接 | Milltina 头＋Milfy 身，作者 HeadReplacingTool 路线 |
| 新头发 | Loose Grace、Lucelia Pony |
| 新衣服 | Silk Kitsune Color9、Marette White Black1、VelourEclipse All Black |
| 道具 | KumaPhone（复用身体原有 SmartPhone 子树）、Takt |
| 功能插件 | Siroari Pose Gimmick、NyaPPu LightController |

**任务拆法**

1. 先做头身拼接与一件衣服，验证真实可见预览；再追加其余衣服、头发。
2. 新发型沿用作者对换入头部施加的坐标映射。当时发现约 4.9 cm 高度差，修正同一候选后贴合；该数值不是其他模型的补偿值。
3. 道具按实际手部归属处理冲突。作者原有包、杖、灯的开关需要保存并恢复。
4. 插件互斥控制实际 Animator 与材质效果。关闭父空对象不会停止已经合并的动画。
5. 原生测试 Pose→Light→关闭→Pose，并在关闭状态尝试旧菜单；确认不能重新开启已关闭效果。
6. 最终候选做一次本地 SDK Build。第一次失败定位到 PB 数量与纹理 mip streaming，后续在私有副本修复并重测。

**最终原生测试范围**

- 14 张最终候选原图逐张查看；三套新服装的指定作者坐姿、完整腿脚通过所测视角检查。
- 两款头发、两道具、插件回切与作者开关恢复实测。
- 灯光退出后核对 420 项材质槽属性，与原基线一致。
- PB 合并按完整配置、组件启用域及相关动画检查；最终 256 个 PB，不代表所有 Avatar 都应该达到这个数值。每组合并会影响同时抓取位置数量，客户端手感仍须实测。
- 私有复制 34 张纹理、22 个材质、53 个动画资源容器，处理 589 处引用，原素材保持不变。
- 最终处理后候选 `Final_R4_Assembly_Processed.prefab`，dependency hash `1248165a1a2d9f22786760f6ef476883`。
- 本地构建包 136,805,785 字节；实际等级 **VeryPoor**，1,122,407 三角面、89 SMR、256 PB、同步参数 174 bits。

未上传、未 Build & Test、未测试 VRChat 客户端，也没有覆盖所有衣服/头发/动作交叉组合。完整场景、商业素材、私人截图及原始会话不随公共工具包分发。

## 案例四：姿势和物理预览不动（真实故障归纳）

在 GM 3.9.8 / SDK 3.10.1 上曾遇到构造入口、PhysBone 初始化和编辑态时钟不兼容。Workbench 0.2.12-dsh 修复这些适配点；未修改 GM/SDK 作者源码。

排查时先看实际链注册、Action 权重、SDK 行为回调与 Editor 更新，不能只看参数变化。如果当前版本不兼容，记录具体异常与缺口；不要删除物理、清空动作或给模型套“所有骨骼归零”的动画来伪造正常画面。

通用经验是把装配、预览兼容、真实控件、图像观察和 SDK 结果分开记录。问题不应仅凭“换了模型后回复更好”就判为解决。
