# 用户手册

## 1. 先准备这三样

1. **DSH 桌面版**：从[官方项目](https://github.com/deepseek-ai/deepseek-harness)获取，在 DSH 自己的模型设置中配置账号，先确认能正常聊天及调用工具。API Key 留在 DSH 设置里，不粘贴到改模需求或工具包。
2. **现有 Unity VRChat Avatars 工程**：使用该工程要求的 Unity 版本，并确保 SDK 和原模型能正常加载。Unity、SDK 和商业素材依赖从各自作者渠道安装。
3. **合法的本地素材**：身体、头部、衣服、头发、Shader 及作者插件。压缩包先按作者说明导入；工具包不代替购买，也不内置这些资源。

本完整包针对 Windows 10/11 x64；Mac、Linux 和 ARM64 没有随包运行环境。Python 与 Node 已随包提供，不需要另装。安装过程本身离线；DSH 模型、首次 Unity 包解析、在线商品搜索仍可能需要网络。

## 2. 安装，一次选好工程

1. 把 ZIP **完整解压到一个固定、可写目录**，例如 `D:\AvatarWorkbench-DSH`。不要在压缩包窗口里直接运行，也不要只复制 Setup 文件。
2. 保存工作并关闭 Unity、DSH，避免两边同时改配置或在复制中途编译。
3. 双击 `Verify-Package.cmd` 检查文件完整性，结果应为 `PASS`。
4. 双击 `Setup.cmd`。输入 Unity 工程根目录，即同时含 `Assets`、`Packages`、`ProjectSettings` 的文件夹。输入不是某个 Prefab 或 Assets 子目录。
5. 脚本先做预检，再安装。成功会显示 `INSTALLED_NOT_UNITY_VERIFIED`；再次运行而无需更新则显示 `UNCHANGED`。
6. 从 Unity Hub 打开这个工程，等待导入、包解析和编译完成。打开 `Tools → 改模工作台（Avatar Workbench）`。
7. 双击 `Doctor.cmd`。`CONNECTION_READY` 表示两个 MCP、目标工程和工作台加载检查通过。它没有修改 Avatar，也没有判定外观合格。
8. 打开 DSH，把本包所在文件夹作为工作区，在其中**新建会话**，粘贴 [FIRST_TASK.md](../examples/FIRST_TASK.md) 的提示词并填入工程和目标。

安装会设置包内 Skill 的路径。第一次生成工作台配置时，需求宿主默认是“当前 DSH”；已有配置保留原选择，如仍显示 Codex/API，请在工作台需求模型中选择“当前 DSH”。

## 3. 正常使用

在 Unity 中选中要编辑的完整 Avatar 根对象，确认工作台正在显示它。工作台素材区域支持本次已选素材、本地目录等来源；在这里添加自己的素材来源或复用已有索引。给 DSH 指定目标素材时，提供实际 Prefab 名称/路径和目标体型，封面仅帮助挑选。

可以在 DSH 中直接说：

> 请在当前工程的候选副本上安装我选中的这件衣服。保留原装和作者开关，让原装与新衣互斥。先完成真实菜单切换，再查看包含完整腿脚的画面。不要上传。

DSH 应先核对工程和当前对象，再动手。用户只需要补充真正缺失的目标或选择；不必重复已经说清的要求。安装完应能在工作台原生衣柜/圆盘上切换，不能只看到一个“成功”回复。

## 4. 反馈一个看得见的问题

停在有问题的候选和状态，保存工作台截图并圈选区域，写明“哪件衣服、哪种姿势、哪里不对、希望变成什么”。选择“当前 DSH”后保存需求，再复制工作台接手指令到 DSH 新消息。

“已读”代表读到反馈，“处理中”代表开始处理，“已回应”代表答复过。只有修正后重新操作和实际看图，才可说问题已修好。保存反馈不会自动唤醒 DSH。

## 5. 怎么判断这次真的完成

- 目标是本次候选，衣服具有真实衣片，预览对象与交付对象一致。
- 可以亲自点 原装→新衣→原装；腿脚、材质、作者部件开关恢复正常。
- 需要物理时开启动态预览，等状态稳定；需要姿势时确认模型确实动了。
- 完整模型交付会记录最终本地 SDK 构建与性能，除非你明确要求不构建。普通单项修改不会自动扩成整模型发布。
- 没有实际看过的图、没有测试的客户端交互，应写“未测试”。构建成功仍可能是 VeryPoor。

运行遇到红色错误或 Doctor 未通过，按 [故障排查](TROUBLESHOOTING.md) 处理。不要通过删除身体、清空所有形态键、放开全部权限或反复换模型来掩盖原因。
