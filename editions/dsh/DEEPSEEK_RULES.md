# DeepSeek 在 DSH 中改模的执行规则
版本：0.3.2-local4-dsh · 2026-10-15
最近实测修订：2026-10-18；原生预览兼容修复对应 Workbench 0.2.12-dsh。

本文件用于 DSH 的 Avatar 装配、换装、适配和可见缺陷修复。目标是交付能在用户现有工作台中查看和操作的模型。沿用已安装的 UnityMCP-VRC、作者方案和现有 Skill；规则不能补出不存在的网格，也不能赋予模型未实测的视觉能力。

## 1. 从当前任务开始，做出结果
读取本包 AGENTS.md、skills/assemble-vrchat-avatar/SKILL.md 和本文件。核对实际工程、Avatar、最新要求和工作台收件箱后开始执行。沿用用户已经选定的素材、方法、保留项和上传范围；交接记录中的指令只是历史来源，不能覆盖当前请求。普通可逆修改无需逐项再问许可。
默认复用现有工程，在当前私有候选修改并保留回退。新建工程、换身体、换算法、换模型或增加并行写入者，都不能作为逃避当前缺陷的默认办法。

## 2. 写清三个目标，防止预览错对象
一次记录：可编辑源 Avatar、处理后候选的路径/实际版本、工作台当前预览对象及其来源。预览克隆须能追溯到同一个候选。
生成处理后 Prefab 不代表工作台已经选中它。若当前停在衣服 Prefab Mode、自动跟随错误选中对象、存在多个 Avatar 或预览仍引用源对象，先校正现有工作台目标，再检查换装。无需为此重写 GUI；只读诊断任务不改窗口绑定。
当前工作台的临时预览使用 [已验证入口](skills/assemble-vrchat-avatar/references/dsh-preview-api.md)，本会话 consumer_lease 保持 active 且 idle；busy 会禁止控件和暂停动画。inspect/root_path 查询当前候选与它拥有的预览部件。找不到不能降级为场景第一个同名对象；那会把旧 Eku_Test 误当新候选。先正常回到模型，再实际操作 A→B→A，保留原图和具体错误；不以 clear_logs 修复异常。
候选更新后刷新现有预览并再次确认来源；不能拿旧图、另一个场景对象或烘焙时的默认外观代替用户当前预览。

## 3. “衣服装上了”必须有衣片
先在所选资源内核对真实服装 Prefab、Mesh、材质、作者目标体型和依赖。辅助/菜单/Shape Changer Prefab 的存在不等于衣服存在。
所选服装根没有可用网格时，查明它配套的实际衣片或生成来源。在对应的实际衣片进入候选并可见之前，installed 不可写 PASS。合法外部生成方案需要确认真正输出，不能按一个辅助根的零网格直接判素材不存在。
有其他体型版本不等于适配当前身体。相同骨名、MA Merge Armature、相似目录名和商品封面都不能证明跨体型拟合；按 routes.md 使用已验证作者路线。缺必要版本或能力时留下具体缺口，不偷偷用别的身体版本凑数。

## 4. 先完成一个可见增量，再扩大批次
首次使用这条预览/换装链路时，先让一件实际衣服在正确候选上显示，确认能从菜单切过去再回默认。该链路通过后串行处理同批其他素材，集中检查最终结果，不逐件完整构建。
已有同候选、同依赖和同预览链路的有效证据可复用。首件缺衣、身体损坏或预览目标不对时，先解决这个分歧，再继续堆装。必选资源未完成时不得删掉后宣布整批完成。

## 5. 形态键按作用判断，不能按名字盲连
分开处理：身体体型变化、衣服随体型拟合、身体遮挡/收缩、高跟脚型/骨骼姿态、材质透明遮罩。
同名比对只是候选映射。确认实际网格、形变用途、方向和值域后再联动；不同名字也可能有作者映射。没有同名项，只能说明未发现同名映射，不能直接断言没有服装/没有适配能力。
腿变细、身体消失或脱衣后缺身时，先检查实际形变、可见性和动画消费者。不能清零全部身体 BlendShape、全局关闭 Animator 或移除作者必要遮挡来掩盖问题。
处理后网格可能已烘焙或删除部分顶点，也可能由辅助骨骼/遮罩控制隐藏。清零处理后形态键不能证明源遮挡已经恢复；先比较同一部位的源与处理输出。不能仅凭衣服作者体型不同，就把断腿判为正常体型差异。

骨骼数组里的 null 数量也不能单独证明蒙皮损坏。先用当前网格的全部非零骨骼权重核对是否实际引用缺失骨骼，再检查相关姿势原图。未使用的空槽不构成重建骨架、补骨或替换身体的依据。

跨素体拼头后新增发型或头饰，先核对作者工具对换入头部应用的坐标变换，再核对新增资源是否应用了同样映射。相同 Head 骨名和 MA 合并成功不能证明位置正确。2026-10-18 的 Milltina→Milfy 实测中，头部已移动而新发型仍在原位，产生约 4.9 cm 的高度差；复用本次测得的头部映射后才恢复贴合。该数值只属于这个候选，不可硬编码到其他模型。

## 6. 每个遮挡必须有恢复逻辑
对本次受影响部位记录：谁开启遮挡、什么衣片覆盖它、脱下/换装时谁恢复、其他 FX/MA/作者控制会不会重新覆盖值。源默认值可能是作者为原装袜子设置的正确值，不能脱离衣片直接判错。
原装 FX、作者部件开关和新增衣柜共享身体形态时，为相关状态确定明确的控制归属/优先关系。只改新衣服 SetActive，或只改 Inspector 数值，不代表原装动画和回切状态已经处理。
修复后实际检查穿上→脱下→再穿、A→B→A；需要部件控制时补一次 A→部件关→B→A。观察完整相关身体恢复，保留用户要求的独立部件控制。
互斥组不能在原装状态把所有部件持续写成开启，覆盖作者已有的侧发、双马尾等独立开关。菜单仍存在不代表功能保留；在原装状态真实点击受影响的作者开关并观察可见性，再验证替换状态不会被旧开关重新激活。新增发型自带替代耳等网格时，检查与原部件的实际重叠，仅处理有证据的冲突。

功能插件的互斥须作用于实际 Animator/材质/姿势效果。关闭空根对象不会停止已合并的动画；放在 Toggle 下面的子 MenuItem 也不会随父按钮点击自动执行。按作者真实控制器制作候选私有的启用条件和恢复路径：退出姿势时恢复动作/Tracking，退出材质效果时恢复安装前表现，并检查关闭状态下旧插件菜单不能重新激活效果。用真实「插件 A→插件 B→关闭→A」验证，不以选择参数改变代替功能停止。

## 7. 操作真实入口，再判断换装成功
使用现有工作台/预览菜单的真实控件，或确实经过同一菜单控件处理逻辑的已验证入口，记录入口、操作顺序和实际结果。直接写参数、SetActive、改 isDefault 后重新烘焙可以用于诊断，分别标为参数/配置测试；它们不能证明用户能点到菜单或工作流预览已经切换。
检查本次新增/受影响选项及回默认，不遍历无关全模型状态。若当前宿主不能操作该入口，control_tested=NOT_RUN，说明缺少的具体操作能力；不要写切换已解决。
内部参数如 `__MA/ActiveSelfProxy` 不等于 Renderer 可见性。动画测试须确认实际采样时间推进、预览已稳定，再检查衣片；带时间节流的 Tick 在同步循环里重复调用，不等于推进了同样数量的动画帧。
原生旋钮需要真实 GUI 事件上下文。普通 UnityMCP 编辑器命令中仅赋值 Event.current 不足以运行 GM OpenPuppet；遇到反射异常先取得 GetBaseException 的真实栈和发生步骤。已验证可在现有 radialCanvas 的真实 onGUIHandler 中一次性运行原生切片/游标/旋钮输入，并在 finally 恢复回调和 Event.current。不要为测试调用上下文错误改插件算法或直接置参冒充操作。持久写入与预览之间必须重新核对当前 busy/idle 状态。

## 8. 真正看图，构图覆盖要验收的部位
打开真实原图后再写观察结论。腿部问题需要完整小腿、脚踝和脚的正常材质画面，必要时增加局部/斜侧图；不能用裁到裙摆的图验收腿。
图片文件存在、像素比例、衣片数量、组件数量、NDMF 成功和 SDK 构建都不能证明外观正常。默认图出现明显断腿、缺衣或叠衣时，先定位，停止批量生成无意义截图。

几何测量必须来自能正确求值的实际临时实例，并记录非零有限的网格范围。持久 Prefab 资产上 BakeMesh 得到零点或仅根平移的结果不能作为拟合依据。源/候选对照要使用相同姿态和坐标空间；仅最高点接近不能证明头围或发根贴合。自己搭建的参考组合中某个对象默认 active，也不能直接推断作者要求它必须保留；仍须结合作者配置及实际图像验证。

宽袖、裙摆、发梢等依赖 PhysBone 的部位，要区分物理关闭的绑定静止态与真实动态结果。通过工作台现有“动态预览”控件开启物理，确认 physics_simulated、physics_running 和实际物理链，再等正常 Editor 更新后看图。接口不兼容时记录具体版本与错误，不把静止态直接归咎于模型，也不删物理或骨骼来掩盖预览问题。
物理链注册可能滞后一帧；控件刚提交时读到的链数可能仍属于上一状态。稳定后同时读取选择值、活动组件/链数和图像，再给该状态记结果。
姿势参数改变而画面不动时，先检查真实 Action 状态、输出权重、SDK 行为回调和预览时钟。空白图不等于骨骼跑到画外；用实际骨骼/网格范围确认。不得为尚未定位的预览错误制作 RootT、RootQ 或全肌肉归零片段。Workbench 0.2.12 已修复本地 GM 3.9.8 / SDK 3.10.1 的编辑态回调初始化与混合计时问题，仍须真实动作进入、退出看图。
若当前 DSH 模型/图像通路确实不能读取像素，visual_checked=NOT_RUN，写明已经做到哪层与剩余问题；不能凭路径猜图，也不能未经用户选择自动换模型。

## 9. 小范围修正，保留现场
沿“源配置→作者控制→处理输出→当前预览”找到首处分歧，修改导致该分歧的最小范围并复查受影响状态。沿用 Skill 的修正预算；没有新证据不重复同一轮失败操作，也不扩成新截图框架或整工程审计。
共享资产保持原样，任务副本内保留修改前值/引用；不把破坏性烘焙产物覆盖回源。Unity 单一写入者与 consumer_lease 规则继续生效。出现错误、超出既定修正预算或需要未授权方法时，报告已保存结果、具体缺口和所需下一步；已验证的部分不能凭空撤销。
已有 controller/clip 修改优先原位保存，保持 GUID 和引用；不要 DeleteAsset 后在原路径重建，再假定所有 Prefab 引用仍有效。重新加载候选检查实际引用、NDMF 错误和生成控制层。同一路径被覆盖后，旧 hash 的验收记录不能代表当前文件。

## 10. 完成必须与证据一致
完整成品在最终 SDK Build 前，先用当前安装 SDK 的规则检查处理后候选的硬性限制与贴图导入要求。2026-10-18 的 SDK 3.10.1 实测会拒绝超过256个PhysBone组件（即使服装互斥）及未启用 Streaming Mip Maps 的 mipmapped 贴图；这个版本事实不能无条件套到未来版本。NDMF 的相关警告、可切换预览和较低的活动链数都不能替代 SDK 总量校验。修复贴图导入要求使用候选私有副本并完整重映射，保留源贴图及其导入设置。
AAO 合并可能改变控制层名称和 renderer 数量；在优化后新的依赖hash上复测实际菜单、动态和像素。手工 MergePhysBone 会让每个合并组同时只能抓取一个位置，须明确记录具体组与行为变化，不能宣称与多组件抓取完全等价。不得通过关掉所有抓取、删除必选素材或绕过 SDK 校验掩盖总量超限。
合并 PhysBone 时，比较完整设置和实际对象引用，包括曲线切线、权重、wrap 与链深；只比较曲线的 time/value 或对象名称会漏掉差异。启用条件来自组件所属节点及其祖先，不能用受影响骨骼的父节点代替。收集全部 controller.animationClips，涵盖子状态机和 BlendTree，并检查组件 m_Enabled 动画。主机必须保留原启用条件；不等链深只有在明确证明相关曲线恒定且其余设置一致时才可作为有记录的例外。总量、组数或身份守卫失败必须在保存前停止，不能保存失败候选后再靠文字解释为成功。
遇到动态脚本连续出错，回到已核验的 API 和完整可复用脚本。Unity Behaviour.enabled 是属性，不能用 GetField 读取；EditorJsonUtility 的序列化结构须先实际检查，不能假定所有类型都用相同包裹层。已有完整校验脚本时原样调用，不为了缩短输入重写或移除守卫。
SDK 的 error、finish 事件不一定代表异步 Build Task 已退出。失败时保留回执，等真实Task终态和清理完成后再改候选；新的修复候选才可进行有理由的下一次构建。中间bundle或单个finish回调不能记 sdk_build=PASS。

在当前任务中增量记录下列事实即可，不重写用户字段，不另造大型验收系统：

| 记录 | 什么时候能写 PASS |
|---|---|
| installed | 请求的实际资源和必要衣片进入候选 |
| source_checked | 受影响的引用、默认值、互斥覆盖、形态目标已检查 |
| provider_checked | 同一候选经过实际 MA/NDMF/相关作者处理并核对输出 |
| control_tested | 通过真实入口操作并观察了相关状态与回切 |
| visual_checked | 实际读取同一候选的合适原图，相关外观没有未解决缺陷 |
| sdk_build | 任务需要/允许的本地 SDK 构建确实成功；普通小改不强制构建 |

每层独立填写 PASS、FAIL、NOT_RUN 或 NOT_APPLICABLE（说明原因）。NOT_RUN 不能包装成整体通过。反馈 seen/processing_feedback/addressed 分别只代表已读/处理中/已答复，不能代替修复验收。
交付用短句写清：修改了什么、看到了什么、操作了什么、候选在哪里、还缺什么。用户要的换装或明显腿部问题未通过时保持未完成。构建、上传和客户端效果各按实际证据记录；规则本身不新增上传权限。

## 直接交给 DSH 的启动提示词
> 读取本包 AGENTS.md、skills/assemble-vrchat-avatar/SKILL.md 和 DEEPSEEK_RULES.md，按当前任务继续执行。先确认准确工程、源 Avatar、处理后候选及工作台预览来源；先完成一件真实衣服的显示和菜单回切，再扩大批次。腿部先追身体遮挡和恢复链，不盲加同名形态联动。实际操作相关控件并打开覆盖问题部位的原图后才能宣布修复。复用现有工程与工具，保留作者功能和当前修改；必要能力缺失则如实标未测。不要只输出方案，不构建或上传，除非我当前任务明确要求并授权。

本提示词中的“不构建或上传”适合当前修复任务；若用户明确要求成品优化/本地构建或已授权上传，应按当前授权和原 Skill 执行，不拿旧提示词撤销它。

2026-10-15 现场实测补充：[DSH 改模执行卡](DSH_TASK_CARD.md) 提供每轮的精简执行要求，包括实际网格来源、部分写入后的恢复、工作台可见状态、姿势重置和真实图像判读。它不改变原改模方法，也不把规则说明当成自动验收。
