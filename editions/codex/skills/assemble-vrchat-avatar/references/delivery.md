# 预算、优化和交付：成品优化与真实结果

## 默认不是发行审计
普通换装/改色不强制安装前 SDK baseline build，不要求每件资源完整 metric snapshot、hash锁或每个增减字节的归因表。当前任务明确要求性能回归对比/发行审计才用原完整路线，原包存于分发包 archive，默认不安装。
这不删除用户需求。已有任务确认的体积、性能等级、功能/胸型范围、画质与默认衣服全部保留；有明确条件就验相应条件。

## 什么时候测量
- 完整 Avatar 成品交付或明确优化：装配正确后执行一次保守优化和最终 SDK 本地 Build 测量；遵守用户禁止构建/优化的限制，或复用相同候选已有构建。按 [optimization.md](optimization.md) 执行。没有基线只报告最终实测，不能造优化百分比。
- 普通单件改色/修复且无性能/体积约束：检查本次结果；不先启动 SDK 构建，不顺带优化整个角色。
- 有明确下载或 SDK 解压体积上限：只对最终候选实际测对应指标。若还要上传，复用同一候选上传构建的实际结果；上传之前若拿不到阻断指标，单独做一次必要测量，不能凭估计上传。
- 有明确 Rank/metric 上限：查询当前平台/SDK实际结果并对比。普通优化只报告实测，不把接近上限当超限。
- 有跨平台要求：按各平台真实能力和约束分别处理，不把PC证据给Android；默认只做当前目标PC，不暗中新增Quest工作。
- 有基线对比要求：才记录必要基线及最终变化；无法还原基线不编造数据。

MB/解压/下载用用户语义或一次澄清，内部明确字节值和指标。模板没有固定300MB或必须Medium，不引用可能过期的硬限制表；用当前SDK实际阻断和用户更严格条件。当前用户只要求符合SDK规定时，Very Poor不是自创阻断，但如实说明性能等级。

## 优化只在有用时发生
完整成品的保守优化已进入默认路线，具体执行与可调用接口见 [optimization.md](optimization.md)。当前工作流自动选阶段；工具计划/回执不能替代真正运行 AAO、看到画面和读到 SDK 输出。
只导入已选款式/平台/必要依赖；不做盲目大合集导入。清理本次无引用残留。已有明确授权的纹理设置可在生成副本执行；没有则不偷偷把头发/衣服统一压到1024或512。
先让核心显示/开关正确再做有损优化，不用删衣服、PhysBone、Contact、重写菜单或冻结滑条换得好看分数。降采样、合并、AAO会影响什么就复查什么，不全工程重拍。
实际开关隐藏的素材也可能纳入统计；不声称关掉就没有成本。仍超明确硬上限时提出最小取舍，未解决不谎称达标。

## 上传
只有当前任务明确“装配并上传”才发布；本包的首次试跑提示词默认本地不上传。之前另一个任务的许可和经验库不是当前授权。只用SDK上传所需构建，不强制Build & Test。
核对精确当前候选/保存状态、目标账号与Blueprint、失败资源撤销、明确要求完成、SDK能上传。已有正确本人任务Blueprint就更新，无ID新建；不挪用旧客户ID、不因404清空ID盲传；Private。
未解决的本次明显视觉/功能缺陷不报完成。用户反馈异常时只定位当前问题，不扩大到全部模型。SDK错误、无权限、登录必要步骤如实报告；不索要密码/Token，不切账号/计费方式。
一次提交等待终态。用户取消或状态不明先核对远端，不重派。确认ID、Private和版本/更新结果，不常规重新下载整个AssetBundle验哈希。
本地效果已看过与客户端网络未测试可以并存。上传确认只证明发布，不证明视觉或客户端效果。
