# 结果检查：小而真实，先看默认画面

这些是实际观察步骤，不是需要另写一套测试程序的清单。检查通过后做下一步；失败时只追首处分歧。

## 开始前确认一次可信预览
使用同一个正确候选；没有旧副本重叠。需要 Provider/NDMF 处理的状态，在真实处理后的预览观察；普通未处理 Scene 不伪称合并结果。保留完整身体、原材质与透明遮罩，采用正常中性光照。
画面缺腿或异常首先比较“完整对象”和“截图可见集合”，避免摄影过程隐藏身体。不要禁掉 Animator 再直接摆参数来证明菜单正确。诊断置值允许，但明确仅用于定位。
不要重写截图框架；使用当前已能正常工作的预览。能力不足说明具体哪项没看到，而不是多写一个 JSON 校验器。

## 默认检查范围
| 本次操作 | 保留的必要观察 | 不额外执行 |
|---|---|---|
| 材质/颜色 | 相关部位正常材质图；确实改了指定槽，其他共享消费者未误染；有切换动画时看颜色不会恢复 | 坐蹲、全衣柜、性能基线 |
| 头饰/道具 | 接触点近景正/斜侧；合适大小；一个典型目标骨活动；要求开关时实际启停 | Body Profile、全身姿态 |
| 上衣/连体衣 | 正常材质完整性；真实开关；抬手/前倾或坐姿中实际相关动作；已启用且受影响的体型控制范围 | 所有控制×所有姿势排列 |
| 裤裙/鞋 | 腰胯/脚踝连续；坐/蹲等相关动作；作者所需脚型；真实脱下→再穿恢复 | 无关上衣/插件检查 |
| 部件/身体遮罩 | 真正控制输入：部件开→关→再开；身体、丝袜、仍开启衣片正确；有套装依赖再做一次 A→部件关→B→A | 只测数值、遍历687种无关状态 |
| 插件 | 用户要的入口/触发→可观察效果；原功能没有受该安装破坏 | 重新测试整个 Avatar |

保留现有启用滑条的受影响范围；用户明确小/默认/大，就按这三个状态查。未启用且没有关联的身体能力不凭空加为要求。一个状态可以同时覆盖多项检查，不为每条字段单拍一张图。
单件修改就是一件的批次。多件任务串行装配，每件拦新错误/明显缺件后继续；全部装完固定最终候选，对每件相关结果集中观察，不每件都做完整构建。

## 首先拒绝肉眼可见错误
默认正常材质图若已有断腿、缺身、衣片丢失、头饰悬空、粉色材质或明显叠衣，不再生成整套姿态图来凑完成数。沿源→作者配置→处理结果→可见结果定位一次。
“对象存在”“687/687数字正确”“NDMF没有异常”“脚出现了”都不能替代完整腿部与实际衣片的观察。
截图必须实际打开，局部要看得清。坐姿确实坐下，抬手确实改变姿态；不是文件名。原材质图看效果，色块临时图找疑似穿出；领口、露肤和透明布料不自动算穿模。

## 不重复检查，但不禁止第一次观察
复用条件：同目标、同相关依赖、同实际状态、同视角、同预览管线，且原图/回执真实存在、已经被观察过。首次观察、新姿态、新用户缺陷、修正后的预览管线都可检查，不以“文件没改”拒绝调查。
修一个材质不重测所有姿态；改身体/共享 FX/Provider 输出后，对受影响资源重查。不能确定依赖是否不变，就补最小相关观察。不得把旧图改标题充当新候选。
每次测试必须改变下一步决定：正常则继续/交付；异常则定位/修复/停止。没有新输入和新问题时不重复同一次失败拍摄。
辅助 `quickflow.py reuse` 只验证记录键和证据文件哈希，不能判断图像中的腿或衣服；调用方造假它无法认证。返回 REUSE_SCOPED_RECORD 也不是整模型通过。

## 结论怎么写
只写人能理解的事实：本地修改完成/仍有具体问题/暂不支持/上传已确认。明确看过哪些效果，未测试的客户端/双人网络行为写未测试，不强制 Build & Test。
任何已知本次引入的明显缺陷不能写完成。单纯候选文件生成和 SDK 上传不是视觉正常。已约定独立复核但没有实际返回，照实说未执行；不自己代写。

## 工作台中的互斥默认与真实输入
新增/修改衣柜或发型组时，先按 [codex-execution.md](codex-execution.md) 的只读 probe 核对实际默认项、互斥目标覆盖、菜单来源和层级。仅查询源配置不能代替合并输出或菜单操作。批次完成后对每个受影响选项实际选择一次，回默认，检查正常材质画面；后加入的发型也必须被原版/马尾等旧选项正确关闭。当前 provider 默认预览与最终客户端分别标明。

## 工作台的预览身份与衣片/遮挡检查
先核对可编辑源、处理后候选、工作台预览来源。生成处理后文件不会自动改变当前预览；Prefab Mode 的衣服对象也不是完整 Avatar。首次走该预览链路，先完成一件实际衣服的显示和真实入口回切，再扩展批次。

辅助 Prefab 零网格时查配套衣片/生成结果，不写服装安装通过。身体体型联动与遮挡恢复分别判断；身体遮挡可能由原装 FX、MA 或部件开关持有，必须在实际脱下/换装后观察恢复。完整腿部验收画面要看到小腿、脚踝和脚；裁到裙摆的图、像素统计、改默认重新烘焙不能证明腿或菜单正常。细则见 [Codex 执行补充](codex-execution.md)。
