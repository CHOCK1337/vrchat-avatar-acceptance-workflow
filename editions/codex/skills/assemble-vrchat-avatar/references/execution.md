# 执行与恢复：避免整工程检查和重复工作

## 连接一次，沿用已经工作的工具
使用已注册 Unity MCP。查一次实际工具与打开实例，核对完整工程路径、目标 Avatar、当前模式与编译/未保存状态。已有正常连接不重装，不改端口，不调整模型权限。请求断线或超时后先读实际目标和回执，可能已经修改，不原样重派。
SDK/MA/Provider 入口以本机已安装版本为准。可以用明确的短 Editor API 操作补胶水，但禁止在用户任务里临时开发通用安装/几何/预览框架，不把发布测试引入装配。
资料只读本次指定目录和真实引用。先返回对象/字段摘要，完整日志留本地；不要不断 Get-Content 整个任务、Hierarchy、工具源文件。常规接口已确认后不要每轮重复探测。

## 任务不是一份新的审计工程
新任务在 `.avatar-assembly/<task>/QuickTask.json` 记目标、资源、明确要求、当前候选、下一动作及少量已完成项即可。只有开始、一个资源/改动批次结束、真正暂停、结束时更新；不要求每个工具调用都写入。
旧 AssemblyTask 只读保留：其中用户确实确认过的要求仍有效。不能把旧“350MB/保留全部/支持某范围”丢掉来提速；但不要为沿用现有模型而伪造旧版全部合同字段。详细升级见包根 MIGRATION.md。
`quickflow.py save` 不导入原始严格任务校验器，不因少性能基线禁止保存进度。它只负责并发版本及原子保存；写入成功不是验收成功。

## 只备份实际改动，不复制工程
保留作者源文件。修改共享 Mesh/Material/Controller 前只复制会改的文件并记录原引用；添加资源保留本次新增对象/组件/引用清单。独立生成候选复用未变资源，不每步另存一份全模型。
恢复必须有旧值或旧文件，只有 hash 不足以撤销。保留当前候选和最近可用候选；清理仅限已证实无引用、本任务创建的临时资产。
禁止为普通换装复制项目、备份 Library/Temp、关闭 Unity、导出整个 UnityPackage、重复 Git 快照。外部高优先级项目指令有冲突，安装阶段处理一次，不递归启动另一个 Skill 的完整备份流程。

## 等待与错误处理
已提交长任务就等待该任务事件/终态。使用工具提供的后台 task/job；没有时在宿主程序里低频等待，不每几秒让模型重新阅读相同日志。发现新错误才返回模型处理。超时不代表没有执行，更不代表可以重复提交。
外层 status=success 可能只是 MCP 接收成功；内层 executionSuccess=false、异常或非零退出码优先。失败后检查部分修改，不能假定事务自动回滚。退出码0也不证明视觉正确。
同一资源同一缺陷预算：一个有依据的纠正事务 + 一次受影响复查。换模型/方法不重新计数。没有新证据而重复同一个失败时停止重试；资料还没读到首处分歧可补一次定向读取，不先改模型猜原因。
修复失败按已授权可选项撤销隔离；必选项、共同身体/菜单被损坏、无法可靠撤销时暂停。不要把“隔离了”当作实现了用户必选功能。

## 不做这些事情
不为了统计减少Token而再运行全部任务A/B；不为学习反复总结全会话；不因“High/max”选项增加测试；不在任务中做角色隔离探针。主控处理当前最影响可见结果的问题，不先写完善报告。确有技术能力缺口就简短说明，不无限研究。
