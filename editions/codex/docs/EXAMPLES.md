# 操作案例与预期检查

以下是给用户复现的操作案例，**不是本版本已经对你的 Avatar 跑过的通过记录**。具体执行结果由当前工程和依赖决定。

## 1. 只接入，不改模型

发送 [FIRST_TASK](../examples/FIRST_TASK.md)。Agent 读工程配置，列出准确实例和真实工具，读取 Skill，尝试绑定当前桌面会话。预期结果分别列出 MCP 可用、Unity 工程匹配、Skill 可读、绑定状态。没有发测试需求，也没有改 Avatar。

## 2. 一件衣服和 A→B→A

> 给当前候选装上所选衣服，保留原衣服和作者部件控制。先确认实际衣片、适配体和依赖，只做这一件，不上传。

Agent 应确认衣服包含可用 Mesh，再在任务副本上接入。真实菜单选择原版→新衣服→原版，查看 B 与返回 A 的原图。要区分外套、上衣、下装的独立开关与整套互斥，不能用一个整套开关声称全部部件可控。

## 3. 腿部消失或变形

> 这张冻结反馈里小腿异常。请核对反馈候选与当前候选，定位具体原因，只修腿部相关项，保留袜鞋与作者体型功能。

Agent 先读 feedback_read，再读原像素 feedback_image。查身体 Renderer/Mesh、当前姿势、骨骼权重、衣服触发的身体隐藏、袜鞋遮罩和换装恢复。修后看站立全身和腿部局部，并实际换装往返。未测姿势/动态写清楚；不能清空全身形态后宣布修好。

## 4. 工作流预览不换衣服

> 我选了另一套衣服，预览还是原来的。请核对当前预览是否读了这次处理后的候选，并验证实际菜单和真实衣片。

先查绑定、候选 asset_path/dependency_hash、source_kind、options；确认衣柜节点不是空辅助对象。自己的 lease 改 active idle，再用公开 preview inspect/select/capture。busy 状态、旧候选、未完成处理、空网格和实际控制失败分别记录，不能靠重新截图证明已修复。

## 5. 换工程或换会话

> 现在改工程 B 的 Avatar，请先解除本会话对工程 A 的工作占用，再读取 B 的已有工作台绑定。保留 A 的任务和反馈。

Agent 在允许时释放自己的 lease，确认 B 的准确实例，context_select 到 B，重新读取任务和反馈。在 B 的 Codex 工程聊天绑定该会话。A 的旧图和读取缓存不得用于确认 B 的反馈。
