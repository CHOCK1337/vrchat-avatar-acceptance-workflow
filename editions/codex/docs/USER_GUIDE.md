# 用户手册

## 一次安装

先按 [开始使用](../START_HERE.md) 完成 Setup、打开 Unity、Doctor、打开同工程 Codex 聊天和首次绑定。安装器选择的必须是 Unity 工程根目录，不能选模型素材文件夹或工具包目录。

安装到工程的内容包括 `Assets/AvatarWorkbench`、缺少的内嵌 UnityMCP/JSON 包、`.codex/config.toml` 中的管理区段、必要的 `.agents/skills/assemble-vrchat-avatar`，以及私有的 `.avatar-workbench-codex`。插件窗口设置保存在用户本机 AvatarWorkbench 的该工程命名空间。全局 Codex 模型、权限、登录资料和无关 MCP 不会被写入。

工作台首次默认选当前 Codex；已有项目保留之前选中的 DSH/API，因此需要在“AI 与模型设置”切回“当前 Codex”。原有 Skill 会原样复用。Doctor 输出只是连接层结果：桌面会话、实际改模和视觉仍需分别验证。

## 第一次操作

从一件适配衣服或一个颜色修改开始。给出 Avatar、资源、想改的地方和保留要求；不要要求 Agent 自行猜测多个同名候选。Agent 应识别源与候选，保存可回退的改动，完成后让你看真实当前模型。

例如：

> 给当前候选装上我选择的外套。保留原衣服和作者部件开关，先确认实际衣片与依赖。完成后实际切换原版→外套→原版，并检查全身、腿部和相关部件。先只做这一件，不上传。

工作台预览有源编辑态、处理后候选和冻结反馈状态。若选衣服后外观不变，先核对当前候选、实际菜单和衣片，不用“成功”日志替代画面。腿部问题要看全腿和鞋子，鞋特写不能证明整条腿已修好。

## 反馈与会话

在真实当前画面圈选问题，写清缺陷，点击发送。原图、圈选、候选身份与请求进入本地收件箱。已绑定且当前桌面支持直送时，送至指定 Codex 会话；失败会保留请求。可把工作台的真实交接文本复制到该聊天继续。

| 状态 | 含义 |
|---|---|
| `binding_pending` | 已提交绑定，尚待桌面会话校验 |
| `accepted` | 桌面接受投递，不代表 Agent 已处理 |
| `seen` | Agent 已读取对应反馈 |
| `addressed` | Agent 已处理这条反馈，不代表外观验收通过 |
| `unknown` | 可能已送达，先核对聊天再重试，避免重复改动 |

会话改变、应用重启或管道失效后，在目标聊天重新做绑定。每个工程有独立配置；不要用另一个工程的聊天继续旧绑定。MCP 通知不是后台自动唤醒保证。

## 更新、移动、回滚

关闭目标 Unity 后重复 Setup。相同文件会跳过；冲突会明确指出位置，不会覆盖本地代码。保留工具包固定路径；移动后从新路径重新安装，重新打开 Codex 工程聊天，使 MCP 读取新配置。

双击 `Rollback.cmd` 回滚此包最近安装的工程；多工程指定 `Rollback.ps1 -Project '你的工程目录'`。只预览用 `-Preview`。遇到安装后的修改会停止，先查看报告；回滚不是删除整个插件目录。备份可能含原来的本地 API 设置，请作为私有数据保存。

快捷方式、完整参数与配置位置见 [MCP 和配置](MCP_AND_CONFIG.md)，常见失败见 [排错](TROUBLESHOOTING.md)。
